# Regenerating the embeddings

Every vector written before `7ac9c99` was produced by a randomly-initialised
model (see that commit). They are noise, and because the random initialisation
differed on every launch of the AI subprocess, vectors written in one app
session were never comparable with another's. There is nothing to salvage.

## Before you start

1. **Build and install the fixed Python service**, or the rebuild just writes
   fresh noise:

   ```bash
   make build-python && make local-install-python
   ```

   Verify it: the service must no longer print `newly initialized` at startup.
   With the fix, a checkpoint that fails to load its weights raises instead of
   serving noise, so a silent success is now a real success.

2. **Quit the app.** The embedding isolates hold the same database.

3. **Back up the database.** It is 308 MB and the delete is not reversible.

   ```bash
   cp ~/Library/Application\ Support/com.xdtlabs.mydatastudio.dev/data/mydata.db ~/Desktop/mydata-backup.db
   ```

## The delete

```bash
sqlite3 ~/Library/Application\ Support/com.xdtlabs.mydatastudio.dev/data/mydata.db "DELETE FROM files_embeddings; DELETE FROM emails_embeddings; VACUUM;"
```

`VACUUM` reclaims the space — roughly 49 MB across the two tables (6,000
vectors × 8 KB).

Nothing else needs clearing. The AI **descriptions** on `files.description` are
generated by the chat model, not the embedding model, and are unaffected — which
matters, because they are the expensive artifact and they are what the
description embeddings are computed *from*. Keyword search over them keeps
working throughout the rebuild.

## What happens next

Relaunch the app. `EmbeddingIsolate`, `FileDescriptionIsolate` and
`EmailEmbeddingIsolate` pick up rows with no embedding and refill both tables in
the background, pausing whenever a scanner is syncing.

Measured on this archive with the fixed model:

| | Count | Rate | Estimate |
|---|---|---|---|
| Descriptions (text) | 2,338 | 0.28 s each | ~11 min |
| Emails (text) | 1,279 | 0.28 s each | ~6 min |
| Images (vision) | 2,373 | see below | the long pole |

Text is quick. Images run the vision tower on CPU — MPS is disabled in
`load_transformers_embedding_model` because Apple Silicon has a PyTorch memory
bug with Qwen-VL's 3D position embeddings — so budget hours, not minutes, and
expect the fans. It is incremental and resumable: search degrades gracefully
while it runs, because a file with no vector is simply absent from the semantic
pass and still fully reachable by keyword.

## Checking it worked

Search `family pictures` once the description pass has run. Before the fix that
query returned mountain goats and wallpaper marketing mail; on a re-embedded
sample of 220 real photos it returns, in order, a family with two young children
in stadium seats, a group of five including children in the snow, and four people
posing at a decorated hedge wall.
